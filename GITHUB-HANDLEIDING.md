# Repository and publication workflow

Use the existing Git checkout and the `dev/beta` branch. Follow [the single beta workflow](BETA-DEVELOPMENT.md). Keep `main` stable and review changes through Git; do not upload loose source files through the browser.

Build artifacts belong in ignored `dist/`. Hardware acceptance and explicit publication approval are required before a merge, release or tag. Prior publication instructions are retained under [docs/history](docs/history/) for reference only.
